## 1. Git and GitHub / Git 与 GitHub

- **Git:** A distributed version control system that can be used locally.<br>**Git：**可在本地使用的分布式版本控制系统。
- **GitHub:** A platform that hosts Git repositories and provides collaboration, automation, security, and project-management features.<br>**GitHub：**托管 Git 仓库并提供协作、自动化、安全和项目管理功能的平台。
- **Repository:** Stores project files and their complete version history.<br>**Repository（仓库）：**保存项目文件和完整版本历史。
- **Commit:** A snapshot of a set of changes with a unique SHA.<br>**Commit（提交）：**一组变更的快照，具有唯一 SHA。
- **Branch:** An independent line of development; the default branch is commonly `main`.<br>**Branch（分支）：**独立开发线；默认分支通常是 `main`。
- **Clone:** Creates a complete local copy of a remote repository.<br>**Clone（克隆）：**将远程仓库完整复制到本地。
- **Fork:** Creates a copy of another repository in your own GitHub account or organization.<br>**Fork（复刻）：**在自己的 GitHub 账户或组织中创建他人仓库的副本。
- **Pull:** Fetches remote changes and integrates them into the current branch.<br>**Pull（拉取）：**获取远程变更并整合到当前分支。
- **Fetch:** Downloads remote references without automatically merging them.<br>**Fetch（获取）：**获取远程信息但不自动合并。
- **Push:** Uploads local commits to a remote repository.<br>**Push（推送）：**把本地提交上传到远程仓库。

### Exam-Style Check 1 / 考试风格练习 1

**Which statement correctly describes GitHub?**  
*哪项陈述正确描述了 GitHub？*

- A. It is only a local version control command.
- B. It is a cloud-based platform that hosts Git repositories and collaboration features.
- C. It replaces Git and does not use repositories.
- D. It can be used only through the command line.

<details><summary>Answer / 答案</summary>

**B.** GitHub is a cloud-based hosting and collaboration platform; Git is the version control system.  
GitHub 是云端托管与协作平台；Git 才是版本控制系统。

</details>

## 2. Repository Fundamentals / 仓库基础

- `README.md`: Introduces the project and explains setup and usage.<br>介绍项目及其安装和使用方法。
- `LICENSE`: States how others may legally use, modify, and distribute the project.<br>说明别人如何合法使用、修改和分发项目。
- `.gitignore`: Specifies files and paths that Git should not track.<br>指定 Git 不应跟踪的文件和路径。
- `CONTRIBUTING.md`: Describes the contribution process and guidelines.<br>说明贡献流程和规范。
- `CODE_OF_CONDUCT.md`: Defines expected community behavior.<br>规定社区行为准则。
- `SECURITY.md`: Explains supported versions and how to report vulnerabilities.<br>说明支持版本和漏洞报告方式。
- `CODEOWNERS`: Assigns code owners to paths and can automatically request reviews.<br>为特定路径指定代码负责人，并可自动请求审查。

### Visibility / 可见性

- **Public:** Anyone can view the repository.<br>所有人都可查看仓库。
- **Private:** Only authorized users can view the repository.<br>仅获授权用户可查看仓库。
- **Internal:** Enterprise members can view the repository; available with GitHub Enterprise Cloud.<br>企业成员可查看，适用于 GitHub Enterprise Cloud。

Internal 仓库对企业成员可见，适用于 GitHub Enterprise Cloud。

</details>

## 3. Issues, Discussions, and Pull Requests / Issue、Discussion 与 Pull Request

- **Issue:** Tracks bugs, tasks, requirements, and other work items.<br>跟踪缺陷、任务、需求和其他工作项。
- **Discussion:** Supports open-ended conversations, questions, and ideas that may not represent specific work.<br>用于开放式交流、问答和想法，不一定对应具体工作。
- **Pull Request (PR):** Proposes merging changes from one branch into another.<br>提议将一个分支的变更合并到另一个分支。
- `Closes #12` or `Fixes #12`: Automatically closes the linked issue when the PR is merged into the default branch.<br>PR 合并到默认分支后自动关闭关联 Issue。
- **Draft pull request:** Indicates that work is in progress and is not ready for formal review or merge.<br>表示工作尚未完成，暂不请求正式审查或合并。

### Pull Request Review Outcomes / PR 审查结果

- **Comment:** Provides feedback without approving or blocking the PR.<br>提出意见，但不表示批准或阻止。
- **Approve:** Approves the proposed changes.<br>批准所提议的变更。
- **Request changes:** Requests modifications and can block merging when required reviews are enabled.<br>要求修改；启用相应规则时可阻止合并。
- **Suggested change:** A specific code change that the author can apply directly.<br>审查者提供的、作者可直接应用的代码修改。

### Merge Methods / 合并方式

- **Merge commit:** Preserves all commits and creates an additional merge commit.<br>保留所有提交，并产生一个额外的合并提交。
- **Squash and merge:** Combines all PR commits into one commit on the base branch.<br>把 PR 的多个提交压缩为目标分支上的一个提交。
- **Rebase and merge:** Adds the commits individually to the tip of the base branch, creating a linear history.<br>把提交依次放到目标分支顶部，形成线性历史。

### Exam-Style Check 3 / 考试风格练习 3

**A team wants a place for open-ended product ideas that do not yet represent planned work. Which feature should it use?**

- A. Issues
- B. Discussions
- C. Pull requests
- D. Releases

<details><summary>Answer / 答案</summary>

**B.** Discussions are intended for open-ended conversations; Issues usually track specific work.  
Discussions 适合开放式交流；Issues 通常跟踪具体工作。

</details>

## 4. Repository Roles / 权限角色

The standard repository roles from least to most access are:  
标准仓库角色通常按权限从低到高排列如下：

1. **Read:** View and clone code and participate in discussions.<br>查看和克隆代码、参与讨论。
2. **Triage:** Manage issues and pull requests without write access to code.<br>管理 Issue 和 PR，但不能推送代码。
3. **Write:** Push code; appropriate for active contributors.<br>可推送代码，适合积极贡献者。
4. **Maintain:** Manage a repository without access to sensitive or destructive actions.<br>管理仓库日常设置，但不能执行部分敏感或破坏性操作。
5. **Admin:** Full repository access, including sensitive and destructive actions.<br>拥有完整管理权限，包括敏感和高风险操作。

**Principle of least privilege:** Grant only the minimum access required to complete a task.  
**最小权限原则：**只授予完成任务所需的最低权限。

### Exam-Style Check 4 / 考试风格练习 4

**A contributor must manage labels and close issues but must not push code. What is the minimum repository role?**  
*贡献者需要管理标签和关闭 Issue，但不能推送代码，最低应授予什么角色？*

- A. Read
- B. Triage
- C. Write
- D. Maintain

<details><summary>Answer / 答案</summary>

**B.** Triage can manage Issues and PRs without granting write access to repository code.  
Triage 可管理 Issue 和 PR，但不会授予代码写入权限。

</details>

## 5. Protected Branches and Rulesets / 分支保护与规则集

Rules can require the following before changes are merged:  
规则可在合并前要求：

- Pull request reviews must be approved.<br>PR 必须通过审查。
- Required status checks must pass.<br>必需状态检查必须通过。
- Conversations must be resolved.<br>所有对话必须解决。
- Commits must be signed.<br>提交必须签名。
- Only specified users or teams may push.<br>仅指定用户或团队可以推送。
- Force pushes and branch deletion can be blocked.<br>可以禁止强制推送或删除分支。

### Exam-Style Check 5 / 考试风格练习 5

**A pull request must pass an automated test workflow before merging. Which rule should be required?**  
*PR 必须通过自动测试工作流后才能合并，应要求哪项规则？*

- A. Required status checks
- B. Required topics
- C. Wiki approval
- D. Repository stars

<details><summary>Answer / 答案</summary>

**A.** A workflow can report a status check, and a ruleset can require that check to pass before merging.  
工作流可报告状态检查，规则集可要求该检查通过后才能合并。

</details>

## 6. GitHub Projects / GitHub 项目

- Plans and tracks work across repositories.<br>用于跨仓库规划和跟踪工作。
- Supports table, board, and roadmap views.<br>支持 Table、Board 和 Roadmap 视图。
- Items can be issues, pull requests, or draft issues.<br>项目条目可以是 Issue、PR 或草稿 Issue。
- Custom fields can store status, priority, dates, iterations, and other metadata.<br>自定义字段可保存状态、优先级、日期、迭代等信息。
- A **milestone** groups issues and pull requests in one repository toward a target or due date.<br>**Milestone（里程碑）**按目标或日期聚合一个仓库中的 Issue 和 PR。

### Exam-Style Check 6 / 考试风格练习 6

**An organization needs a roadmap that tracks work from several repositories. Which feature should it use?**  
*组织需要用路线图跟踪多个仓库中的工作，应使用哪项功能？*

- A. GitHub Projects
- B. A repository milestone
- C. A release tag
- D. CODEOWNERS

<details><summary>Answer / 答案</summary>

**A.** GitHub Projects can plan and track work across repositories; a milestone groups work in one repository.  
GitHub Projects 可跨仓库规划和跟踪工作；Milestone 聚合单个仓库内的工作。

</details>

## 7. GitHub Actions / GitHub Actions

- **Workflow:** An automated process defined by a YAML file in `.github/workflows/`.<br>位于 `.github/workflows/` 中、由 YAML 文件定义的自动化流程。
- **Event:** Activity that triggers a workflow, such as `push` or `pull_request`.<br>触发工作流的事件，如 `push` 或 `pull_request`。
- **Job:** A set of steps executed on the same runner.<br>在同一 runner 上执行的一组步骤。
- **Step:** An individual task that runs a command or an action.<br>运行命令或 action 的单个任务。
- **Runner:** A machine that executes jobs.<br>执行 job 的计算环境。
- **Action:** A reusable unit of automation, which can be obtained from GitHub Marketplace.<br>可复用的自动化组件，可从 GitHub Marketplace 获取。
- Store secrets in GitHub Secrets; never commit them to code.<br>Secret 应保存在 GitHub Secrets 中，不应提交到代码中。

### Exam-Style Check 7 / 考试风格练习 7

**Which GitHub Actions component is the machine that executes the steps in a job?**  
*哪个 GitHub Actions 组件是执行 job 中各步骤的计算机？*

- A. Event
- B. Workflow
- C. Runner
- D. Action

<details><summary>Answer / 答案</summary>

**C.** A runner is the machine that executes jobs; a job contains one or more steps.  
Runner 是执行 job 的计算机；job 包含一个或多个 step。

</details>

## 8. Development Environments / 开发环境

- **github.dev:** A browser-based editor without a complete cloud compute environment; useful for quick edits.<br>浏览器编辑器，无完整云端计算环境，适合快速编辑。
- **Codespaces:** A cloud-hosted development environment with compute resources, a terminal, and configurable containers.<br>云端开发环境，提供计算资源、终端和可配置容器。
- **Local VS Code:** Uses the runtimes and resources on your own computer.<br>使用本机的运行时和资源。

- B. GitHub Codespaces

</details>

## 9. Security Features / 安全功能

- **2FA / passkey:** Strengthens account sign-in security.<br>加强账户登录安全。
- **Personal access token (PAT):** Authenticates HTTPS or API access and should have the minimum scope and lifetime.<br>用于 HTTPS 或 API 身份验证，应设置最小作用域和有效期。
- **SSH key:** Provides secure authentication to GitHub over SSH.<br>用于通过 SSH 安全连接 GitHub。
- **Dependency graph:** Identifies a project's dependencies.<br>识别项目依赖。
- **Dependabot alerts:** Notify you about dependencies with known vulnerabilities.<br>提醒存在已知漏洞的依赖。
- **Dependabot security updates:** Create pull requests to update vulnerable dependencies.<br>创建 PR 来更新易受攻击的依赖。
- **Secret scanning:** Detects tokens, keys, and other secrets committed to a repository.<br>查找意外提交的令牌、密钥和其他秘密。
- **Push protection:** Blocks detected secrets before they are pushed.<br>在推送前阻止检测到的秘密。
- **Code scanning:** Analyzes code for security vulnerabilities and coding errors.<br>分析代码中的安全漏洞和编码问题。
- Removing a leaked secret from a file is not enough; revoke or rotate the credential immediately.<br>发现敏感信息后，仅删除文件还不够，必须立即撤销或轮换凭据。

### Exam-Style Check 9 / 考试风格练习 9

**Secret scanning reports that a valid PAT was committed. What should you do first?**  
*Secret scanning 报告一个有效 PAT 被提交，首先应该做什么？*

- A. Delete only the latest commit.
- B. Make the repository private.
- C. Revoke or rotate the PAT.
- D. Disable secret scanning.

<details><summary>Answer / 答案</summary>

**C.** Revoke or rotate the credential immediately to reduce risk. Removing it from Git history alone does not invalidate it.  
应立即撤销或轮换凭据以降低风险；仅从 Git 历史中删除并不会使其失效。

</details>

## 10. Community and InnerSource / 社区与 InnerSource

- **Open source:** Source code is public, and a license defines how it may be used.<br>源码公开，并由许可证规定使用权利。
- **InnerSource:** Applies open-source collaboration practices within an organization.<br>在组织内部采用开源式协作方法。
- Healthy InnerSource indicators include contributor growth, more cross-team PRs, and improved response and merge times.<br>健康的 InnerSource 指标包括贡献者增长、跨团队 PR 增加，以及响应和合并时间改善。
- **Star** bookmarks or shows appreciation; **Watch** controls repository notifications; **Fork** creates a personal copy.<br>Star 表示收藏或认可；Watch 控制仓库通知；Fork 创建个人副本。

### Exam-Style Check 10 / 考试风格练习 10

**What does InnerSource mean?**  
*InnerSource 是什么意思？*

- A. Publishing all company code publicly
- B. Applying open-source collaboration practices within an organization
- C. Restricting contributions to repository admins
- D. Storing source code only on local computers

<details><summary>Answer / 答案</summary>

**B.** InnerSource uses open-source working practices for collaboration inside an organization.  
InnerSource 是在组织内部采用开源式协作实践。

</details>

## 11. Search Quick Reference / 搜索速查

```text
repo:owner/name is:issue is:open label:bug
repo:owner/name is:pr is:open author:username
org:organization-name language:python
```

### Exam-Style Check 11 / 考试风格练习 11

**Which query finds open pull requests created by `octocat` in `contoso/app`?**  
*哪个查询可查找 `contoso/app` 中由 `octocat` 创建的开放 PR？*

- A. `repo:contoso/app is:pr is:open author:octocat`
- B. `repo:contoso/app is:issue closed:octocat`
- C. `git find octocat pull-request`
- D. `org:octocat language:open`

<details><summary>Answer / 答案</summary>

**A.** `repo:` limits the repository, `is:pr` selects pull requests, `is:open` selects the state, and `author:` filters the creator.  
`repo:` 限定仓库，`is:pr` 选择 PR，`is:open` 限定状态，`author:` 筛选创建者。

</details>

## 12. Markdown Quick Reference / Markdown 速查

```markdown
# Heading / 一级标题
**Bold / 粗体**
*Italic / 斜体*
***Bold italic / 粗斜体***
[Link text / 链接文字](https://github.com)
- [ ] Task / 待办任务
`Inline code / 行内代码`
```

Add a language name such as `javascript` after the opening three backticks to enable syntax highlighting. Use `<br>` to force a line break in GitHub Markdown.  
在代码块开头的三个反引号后指定 `javascript` 等语言可启用语法高亮。`<br>` 可在 GitHub Markdown 中强制换行。

</details>

## 13. Commonly Confused Concepts / 高频易错对比

| Concepts / 易混概念 | Correct distinction / 正确区分 |
|---|---|
| Git / GitHub | Git is a version control system; GitHub is a hosting and collaboration platform.<br>Git 是版本控制系统；GitHub 是托管与协作平台。 |
| Clone / Fork | Clone copies a repository locally; Fork copies it to your GitHub account or organization.<br>Clone 复制到本地；Fork 复制到自己的 GitHub 账户或组织。 |
| Fetch / Pull | Fetch does not merge automatically; Pull normally fetches and integrates changes.<br>Fetch 不自动合并；Pull 通常获取并整合变更。 |
| Issue / Discussion | An Issue tracks specific work; a Discussion supports open-ended conversation.<br>Issue 跟踪具体工作；Discussion 用于开放交流。 |
| Triage / Write | Triage cannot push code; Write can push code.<br>Triage 不能推送；Write 可以推送。 |
| github.dev / Codespaces | github.dev is mainly an editor; Codespaces provides cloud compute.<br>前者主要用于编辑；后者提供云端计算环境。 |
| Secret scanning / Code scanning | Secret scanning finds exposed credentials; code scanning analyzes vulnerabilities in code.<br>前者查找泄露凭据；后者分析代码漏洞。 |
| Project / Milestone | A Project can plan across repositories; a Milestone groups work within one repository.<br>Project 可跨仓库规划；Milestone 聚合一个仓库内的工作。 |
