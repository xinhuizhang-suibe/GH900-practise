# GH-900 Practice Questions / 练习题

## Questions / 题目

1. What is the lowest appropriate repository role for a contributor who needs to push code directly?  
   *需要直接向仓库推送代码的贡献者，最低应具有什么权限？*
   - A. Read / 读取
   - B. Triage / 分类
   - C. Write / 写入
   - D. Admin / 管理

2. Which command downloads the latest remote branch information without merging it?  
   *哪个命令获取远程分支的最新信息，但不进行合并？*
   - A. `git fetch`
   - B. `git pull`
   - C. `git push`
   - D. `git clone`

3. Which file explains how to report a security vulnerability?  
   *哪个文件说明如何报告安全漏洞？*
   - A. `README.md`
   - B. `SECURITY.md`
   - C. `.gitignore`
   - D. `CODEOWNERS`

4. A team requires automated tests to pass before a pull request can be merged. What should it configure?  
   *团队要求 PR 必须通过自动测试后才能合并，应配置什么？*
   - A. Wiki / 维基
   - B. Required status checks / 必需状态检查
   - C. Repository topic / 仓库主题
   - D. Release / 发布版本

5. Which feature is best suited to open-ended questions and idea sharing?  
   *哪项功能最适合开放式问答和想法交流？*
   - A. Discussions / 讨论
   - B. Pull requests / 拉取请求
   - C. Releases / 发布版本
   - D. Commits / 提交

6. Which merge method combines multiple pull request commits into one commit on the base branch?  
   *哪种合并方式会把 PR 中多个提交整理为目标分支上的一个提交？*
   - A. Merge commit / 合并提交
   - B. Squash and merge / 压缩合并
   - C. Rebase and merge / 变基合并
   - D. Fetch / 获取

7. Which GitHub Actions component is the machine that executes a job?  
   *哪个 GitHub Actions 组件是实际执行 job 的计算环境？*
   - A. Event / 事件
   - B. Runner / 运行器
   - C. Secret / 机密
   - D. Marketplace / 市场

8. Which environment provides complete cloud compute resources and a terminal in the browser?  
   *哪个环境在浏览器中提供完整的云端计算资源与终端？*
   - A. github.dev
   - B. GitHub Pages
   - C. Codespaces
   - D. Wiki

9. Which feature detects access tokens that were accidentally committed to a repository?  
   *哪项功能用于发现代码库中意外提交的访问令牌？*
   - A. Code scanning / 代码扫描
   - B. Secret scanning / 机密扫描
   - C. Dependency graph / 依赖关系图
   - D. Projects / 项目

10. What should you do first after a personal access token (PAT) is exposed?  
    *PAT 泄露后，首先应该怎么做？*
    - A. Only delete the file containing the PAT. / 只删除包含 PAT 的文件。
    - B. Make the repository private. / 将仓库改为 private。
    - C. Revoke or rotate the PAT immediately. / 立即撤销或轮换 PAT。
    - D. Create an issue. / 创建 Issue。

11. Which keyword can automatically close Issue 12 when a pull request is merged?  
    *哪个关键词可让 PR 合并时自动关闭 Issue 12？*
    - A. `Mentions #12`
    - B. `Closes #12`
    - C. `Tracks #12`
    - D. `Reviews #12`

12. Which role can manage issues and pull requests but cannot push code?  
    *哪种角色可以管理 Issue 和 PR，但不能向仓库推送代码？*
    - A. Read / 读取
    - B. Triage / 分类
    - C. Write / 写入
    - D. Maintain / 维护

13. What does `.gitignore` do?  
    *`.gitignore` 的作用是什么？*
    - A. Deletes remote branches. / 删除远程分支。
    - B. Specifies files that Git should not track. / 指定 Git 不应跟踪的文件。
    - C. Assigns code reviewers. / 指定代码审查者。
    - D. Stores account passwords. / 保存账户密码。

14. What is the primary purpose of `CODEOWNERS`?  
    *`CODEOWNERS` 的主要作用是什么？*
    - A. Automatically assigns code owners or reviewers for specified paths. / 自动指定特定路径的代码负责人或审查者。
    - B. Records proof of repository ownership. / 记录仓库所有权证明。
    - C. Manages GitHub billing. / 管理 GitHub 账单。
    - D. Creates a software license. / 创建软件许可证。

15. Which search query finds open issues labeled `bug` in a specific repository?  
    *哪个搜索查询用于查找指定仓库中带有 `bug` 标签的开放 Issue？*
    - A. `repo:owner/name is:issue is:open label:bug`
    - B. `owner/name open bug`
    - C. `git find bug`
    - D. `is:commit label:bug`

16. A pull request is unfinished, but its author wants early feedback. What should the author use?  
    *一个 PR 尚未完成，但作者希望提前获得反馈，应使用什么？*
    - A. Release / 发布版本
    - B. Draft pull request / 草稿拉取请求
    - C. Security advisory / 安全公告
    - D. Milestone / 里程碑

17. What do Dependabot security updates typically do?  
    *Dependabot security updates 通常会做什么？*
    - A. Delete the repository. / 删除仓库。
    - B. Create pull requests that update vulnerable dependencies. / 创建更新易受攻击依赖的 PR。
    - C. Change repository visibility. / 更改仓库可见性。
    - D. Approve every pull request. / 审批所有 PR。

18. What is GitHub Marketplace used for?  
    *GitHub Marketplace 的作用是什么？*
    - A. Buying and selling source code. / 买卖源代码。
    - B. Finding integrations such as GitHub Apps and Actions. / 查找 GitHub Apps 和 Actions 等集成。
    - C. Storing Git commits. / 保存 Git 提交。
    - D. Creating local branches. / 创建本地分支。

19. What is InnerSource?  
    *InnerSource 是什么？*
    - A. A requirement to publish all code publicly. / 只允许公开发布代码。
    - B. The use of open-source collaboration practices within an organization. / 在组织内部采用开源式协作方法。
    - C. A Git merge strategy. / 一种 Git 合并策略。
    - D. A type of license. / 一种许可证。

20. How are repository wiki pages typically maintained?  
    *仓库 Wiki 页面通常如何维护？*
    - A. Only repository owners can edit them with the CLI. / 只能由仓库所有者使用 CLI 编辑。
    - B. Users with appropriate permissions can edit them on GitHub. / 具有适当权限的用户可通过 GitHub 网页编辑。
    - C. Only GitHub employees can edit them. / 只能由 GitHub 员工编辑。
    - D. They cannot retain revision history. / 不能保留历史记录。

1. **C.** Write is the lowest role that allows a user to push code.<br>Write 是允许用户推送代码的最低角色。
2. **A.** Fetch downloads remote information without automatically merging it.<br>Fetch 获取远程信息但不自动合并。

4. **B.** Required status checks can be enforced as a merge requirement.<br>Required status checks 可设为合并条件。
5. **A.** Discussions support open-ended conversation, while issues usually track specific work.<br>Discussions 适合开放交流；Issue 通常跟踪具体工作。
6. **B.** Squash and merge combines multiple commits into one.<br>Squash and merge 将多个提交压缩为一个。
7. **B.** A runner provides the compute environment that executes a job.<br>Runner 提供执行 job 的计算环境。
8. **C.** Codespaces provides a complete cloud-hosted development environment.<br>Codespaces 提供完整的云端开发环境。
9. **B.** Secret scanning detects exposed tokens, keys, and other secrets.<br>Secret scanning 专门检测暴露的令牌、密钥等秘密。
10. **C.** Revoke or rotate an exposed credential immediately; deleting the file does not invalidate it.<br>泄露凭据必须立即撤销或轮换；删除文件不能使其失效。
11. **B.** `Closes #12` can close the linked issue when the PR is merged.<br>`Closes #12` 可在 PR 合并时关闭关联 Issue。
12. **B.** Triage can manage issues and PRs but cannot push code.<br>Triage 可管理 Issue 和 PR，但不能推送代码。
13. **B.** `.gitignore` specifies paths that Git should not track.<br>`.gitignore` 指定不应被 Git 跟踪的路径。
14. **A.** CODEOWNERS assigns owners by path and can automatically request their review.<br>CODEOWNERS 按路径指定负责人，并可自动请求审查。

16. **B.** A draft PR signals that the changes are not ready for formal review or merge.<br>Draft PR 表示变更尚未准备好正式审查或合并。
17. **B.** Dependabot security updates propose dependency upgrades in pull requests.<br>Dependabot security updates 会通过 PR 提议依赖升级。
18. **B.** Marketplace provides GitHub Apps, Actions, and other integrations.<br>Marketplace 提供 GitHub Apps、Actions 和其他集成。
19. **B.** InnerSource applies open-source collaboration practices within an organization.<br>InnerSource 把开源协作实践应用于组织内部。
20. **B.** Users with appropriate permissions can maintain a wiki through GitHub.<br>具有适当权限的用户可通过 GitHub 维护 Wiki。
